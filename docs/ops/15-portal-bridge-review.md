# Studio Brain Portal Bridge Review

Snapshot: 2026-05-06, captured read-only with `scripts/ops/portal_bridge_review.sh --ssh-host studiobrain`.

This note documents the localhost Control Tower proxy and reverse SSH tunnel that make Studio Brain admin surfaces reachable through the portal bridge path. It is evidence only; it does not approve service restarts, SSH key changes, firewall changes, or tunnel endpoint changes.

The drift checker classifies both service files as generated by `scripts/install-studiobrain-portal-bridge.sh`. That is intentional because the tunnel target, port, key path, and proxy upstream are install-time values and should not be hard-coded into static repo config without a separate security review.

## Risk

- A high historical restart count can hide transient tunnel instability even when the service is currently active.
- Restart churn can mask remote port conflicts, network interruptions, SSH keepalive failures, or key permission issues.
- The proxy and tunnel are operational glue. A broken bridge can make admin surfaces look down even when the underlying Studio Brain API is healthy.

## Safe Next Step

1. Keep `make ops-portal-bridge-review` or `bash scripts/ops/portal_bridge_review.sh --ssh-host studiobrain` in the weekly ops check.
2. If the tunnel restart count keeps increasing, inspect the service journal and remote endpoint availability before restarting.
3. If the proxy is inactive, check the Studio Brain API health and proxy journal before restarting.
4. Do not print private key contents, environment values, or tunnel credentials into reports.

## Approval Boundary

Requires explicit approval:

- restarting either service
- changing SSH keys, tunnel users, remote hosts, or remote ports
- editing firewall rules or SSH server configuration
- replacing install-time interpolation with static unit files
