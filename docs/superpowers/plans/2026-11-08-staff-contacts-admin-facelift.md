# Staff Contacts and Administration Implementation Plan

> **For the implementing agent:** Start a clean branch from current `origin/main` after PR #843. Work in the two independently reviewable slices below. This is a build handoff; no production deployment is part of it.

**Goal:** Staff can find a person and start an email in seconds, and can open any Administration page and see what needs attention and what to do next.

**Architecture:** Keep the existing React/TypeScript staff shell, route contracts, data, authorization, and write handlers. Use semantic HTML, scoped CSS, small SVGs, and existing React state. Generated artwork is self-hosted and decorative; the HTML workflow is the source of meaning.

## Slice 1 — Contacts, with email first

**Owners:** `web/src/views/StaffView.tsx` (directory, `loadUsers`, selection and messaging), `web/src/views/staff/StaffWorkspaceNav.tsx` (label), `web/src/views/staff/staffWorkspace.css` and `web/src/App.css` (layout), `web/src/utils/staffWorkspacePaths.ts` (routes). Add a focused presentation component `web/src/views/staff/StaffContacts.tsx` only if it keeps the data and permission plumbing in place. Tests: `StaffView.ui.test.tsx`, `MessagesView.test.tsx`, `staffWorkspacePaths.test.ts`.

- [ ] Rename the visible entry and heading to **Contacts**. Keep `/staff/cockpit/members` as the working bookmark. Remove the membership-service section, membership promotion and member-only filters from this workflow. Keep existing people and their history; a person with a portal membership remains searchable. Preserve audited role management for authorized admins as a separate task in Policies & integrations, using the same authorization, self-lockout guard and audit reason; do not remove or expose backend capabilities. Do not touch the public membership route or delete data as part of this staff facelift.
- [ ] Put one visible, labelled “Search by name or email” field directly above results. Retain first-entry refresh, in-flight guard, and a quiet Retry on failure. Remove the search-focus button and default role badges. Show name and wrapping email with only useful channel cues. At narrow content widths use one column: search/results, then a focused detail view with “Back to results” restoring query and focus. Only use list/detail side by side when the *content container* has space for both; set grid children to `min-width: 0` and allow long addresses to wrap.
- [ ] For a selected result, make **Email** the first action. Reuse an existing approved single-recipient external email compose flow if present; otherwise use a validated, single-address `mailto:` draft. Reject newline/header injection and malformed or multi-address values; keep “Copy email” beside the action for systems without a default mail app. Use an explicit **Message in portal** action only for a confirmed portal account and a supported staff compose path. Keep it inside the existing staff Messages shell. Inspect the real recipient/compose contract before wiring it; if no targeted compose path exists, report that dependency instead of presenting a generic inbox as a prefilled conversation. Never auto-send or log a draft or address in telemetry. Show “No email on file” or “No portal account” where appropriate.
- [ ] Make existing authorized external-only contacts searchable even when the users/profile result is nonempty. Verify the existing approved contact source and its search/pagination contract before wiring it. Do not repurpose the current broad fallback scans or classify an inferred UID as a portal account. Merge records only on a trusted shared identity; preserve separate records with ambiguous matches. Show “Search is limited to available contacts” when the source is bounded or partially unavailable. If no approved external-contact source exists, report it as a separate dependency and make clear which known records this slice searches. Allow a staff-entered valid email to open a draft without saving or importing a contact.
- [ ] Add fixture cases for external-only, portal-only, both channels (email first), missing email, ambiguous duplicate names and partial failure. Assert links/recipient state without sending mail. Test entry refresh, legacy bookmark, keyboard selection, back/focus restoration and unchanged non-admin privileges. Commit this slice separately.

## Slice 2 — Administration as a set of staff tools

**Owners:** `web/src/views/staff/CockpitOpsPanel.tsx`, `PolicyModule.tsx`, `AgentOpsModule.tsx`, `StudioBrainControlTowerModule.tsx`, `StaffWorkspaceNav.tsx`, `staffWorkspace.css`, `admin/AdminWorkspace.tsx`, and `web/public/staff-admin/`. The admin module files are under `web/src/views/staff/`. Existing coverage: `web/src/views/StaffView.ui.test.tsx`, `web/src/views/staff/CockpitModule.test.tsx`, `web/src/views/staff/StudioBrainControlTowerModule.test.tsx`.

- [ ] Start with Policies. Give it one full-width top section and an ordinary vertical document beneath it. Remove the empty grid cell and prevent artwork from taking the height of the neighboring forms. Inspect the outer staff grid and its breakpoints; add an admin-specific layout rather than rewriting unrelated layouts. Keep one sidebar and use visible in-page headings or direct anchor links. Move raw details behind one flat diagnostics disclosure where necessary. No navigation inside navigation.
- [ ] Give each page one question, one primary action or entry point, and an infographic matched to the task. Use the following as the content contract:

| Page | What staff needs to do | Graphic and motion |
| --- | --- | --- |
| Policies & integrations | See what is enabled, then go straight to Access & roles, Policies, or Integrations. Put dangerous controls with their reason and confirmation. | Seal-and-key background; a short Request → Identity → Rule → Outcome reveal. Label it as a guide, not a live decision. |
| System health | See what needs attention and run a read-only check. Put raw output and failure drills below. | Service circuit; highlight each check only when its real result is available. Distinguish unchecked, running, failed, and passed. |
| Automations | See failures and stale results first; open the exact run. | Workshop conveyor; emphasize reported states with a brief reveal, never pretend a job advanced. |
| Usage reports | Understand this browser's activity and inspect the counts or timings. | Tally-sheet background and one bar entrance; keep exact values and local-only scope visible. |
| Studio Brain | Review approvals and blocked work first; open the relevant room, run, or service. | Workshop dispatch board; briefly highlight the real handoff or pending review, then settle. |

- [ ] Generate coordinated wide backgrounds with open space behind text; no generated text, fake controls, or numbers baked into art. Reuse #843 art where it suits the layout. Add the same visual language to Contacts (address book or correspondence shelf), with one restrained selection or results transition. Store optimized WebP locally (aim at or below 60 KB per image); use scoped CSS backgrounds, a legible scrim and a solid fallback. HTML carries headings, labels, steps, and values. Keep motion to one short sequence per page using transform/opacity, stop with `prefers-reduced-motion`, never hide or delay controls, and avoid repeated entrance motion on refresh. Load shared admin CSS from the staff/admin entry, so Studio Brain works on a direct visit. Avoid global animation names and runtime style injection.
- [ ] Verify every existing action is reachable and keeps its current guard. Empty, stale, unavailable and failed are distinct; missing data must not read as zero or healthy. Exercise switches/approvals only against fixtures or an emulator. Verify sidebar and in-page destinations, reload, browser back and current-page styling. Commit admin layout/policy first and then the remaining pages so review can isolate regressions.
